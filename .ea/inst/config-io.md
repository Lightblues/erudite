# UserDefaults vs NSUbiquitousKeyValueStore (KVS)
┌────────────────┬───────────────────────────────────┬──────────────────────────────────────────────────────────────────────┐
│      维度      │           UserDefaults            │                      NSUbiquitousKeyValueStore                       │
├────────────────┼───────────────────────────────────┼──────────────────────────────────────────────────────────────────────┤

│                │ eID>.plist                        │                                                                      │
├────────────────┼───────────────────────────────────┼──────────────────────────────────────────────────────────────────────┤
│ 跨设备同步     │ ❌                                │ ✅ 自动                                                              │
├────────────────┼───────────────────────────────────┼──────────────────────────────────────────────────────────────────────┤
│ API            │ UserDefaults.standard.set(...)    │ NSUbiquitousKeyValueStore.default.set(...) 几乎一样                  │
├────────────────┼───────────────────────────────────┼──────────────────────────────────────────────────────────────────────┤
│ 容量           │ 实际无限(几 MB 都没事)            │ 总 1 MB,单 key 1 MB,最多 1024 keys                                   │
├────────────────┼───────────────────────────────────┼──────────────────────────────────────────────────────────────────────┤
│ 类型           │ 同 plist(Bool/Int/String/Data/Arr │ 同                                                                   │

典型用法:大多数项目两个一起用——本地永远写 UserDefaults(权威 cache),同时也写 KVS(同步通道),启动时和收到 didChangeExternallyNotification 时把 KVS 值合并回 UserDefaults。这样离线、未登 iCloud 的用户也完全无感,登了 iCloud 的用户自动得到同步。

我的判断:
- 一步步来, 首先去除 json 形式的配置项, 采用 GUI 来管理配置 -- 用户更友好.
- 是否使用 iCloud? 没必要! 自己没有付费账号体验也不好, 全部本地存储即可!
- 真的要做跨设备同步? 短期是让用户在本地单设备使用的 (实际上没什么同步需求!) 
  - 我感觉, 真的有需要的可能是导入导出功能 -- e.g. 用户换设备了, 或者想导出数据做分析. 后续可提供导出/导出配置/应用数据的能力. 你觉得合理吗
